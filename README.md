# Примеры гардрейлов для AI-агентов

Здесь лежат минимальные воспроизводимые примеры для статьи про гардрейлы и безопасную работу с AI-агентами.

В репозитории два примера:

1. Детерминированный input rail на [NVIDIA NeMo Guardrails](https://github.com/NVIDIA-NeMo/Guardrails). Он проверяет сообщение пользователя на SQL-операции `DROP`, `DELETE` и `TRUNCATE` до вызова основной модели.
2. MCP-сервер перед семантическим слоем MetricFlow. Агент видит только разрешённые метрики и измерения, а не произвольный SQL и учётные данные DWH.

## Что внутри

- `config/actions.py` — Python-action с детерминированной проверкой;
- `config/rails.co` — Colang-flow, который возвращает отказ и останавливает обработку;
- `config/config.yml` — подключение flow, локальной модели Ollama и JSONL-трассировки;
- `app.py` — минимальный HTTP API на FastAPI;
- `example.sh` — проверочный запрос из статьи;
- `tests/` — небольшие тесты правила.

Файлы второго примера находятся в `semantic_layer_mcp/`:

- `semantic_models.yml` — определение модели `orders` и метрики `revenue`;
- `example.sh` — соответствующие команды MetricFlow CLI;
- `server.py` — MCP-интерфейс с allowlist, ограничением периода, строк и времени выполнения.

## Запуск

Нужны Python 3.10+ и [Ollama](https://ollama.com/) с моделью `llama3.1`.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
ollama pull llama3.1
uvicorn app:app --reload
```

В другом терминале:

```bash
./example.sh
```

Ожидаемый ответ:

```json
{"reply":"Запрос заблокирован политикой."}
```

Для заблокированного запроса основная модель не вызывается. Для безопасного сообщения приложение передаст запрос локальной `llama3.1`. Трассы пишутся в `logs/traces.jsonl` и не коммитятся.

## MCP для семантического слоя

Этот пример предполагает, что локальная команда `mf` уже настроена для вашего dbt/MetricFlow-проекта. Файл `semantic_models.yml` — минимальный фрагмент, который нужно положить в каталог `models/` такого проекта рядом с моделью `fct_orders`.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r semantic_layer_mcp/requirements.txt
fastmcp run semantic_layer_mcp/server.py
```

По умолчанию сервер использует stdio: MCP-клиент сам запускает этот процесс. Сервер предоставляет два инструмента:

- `list_metrics` — фиксированная команда просмотра каталога метрик;
- `query_metrics` — запрос только разрешённых метрик и разрезов на период не больше 366 дней, максимум 1000 строк.

Команда собирается как список аргументов без shell. Каждый запрос получает отдельный временный CSV, поэтому параллельные вызовы не перезаписывают общий `/tmp/out.csv`.

## Проверка

```bash
pip install -r requirements-dev.txt

```

## Ограничения примера

Регулярка проверяет слова, а не намерение. Например, фраза «удали таблицу customers» пройдёт проверку, хотя модель может превратить её в `DROP TABLE`. В реальном агенте проверку опасных операций лучше ставить на аргументы инструмента, а окончательную границу — в права БД: отдельная роль без `DROP`, `TRUNCATE` и записи.

MCP-пример тоже не решает авторизацию пользователей и row-level security. Процесс MetricFlow должен работать под отдельной ролью только для чтения нужных витрин. Allowlist в коде ограничивает интерфейс агента, но не заменяет права DWH.
